## 1. 产品概述

**一句话定位**：aquant 是一款本地优先的 A 股量化研究报告研究桌面应用——用户粘贴 PTrade 等平台的量化报告，多 Agent 自动完成解析、查证与风险复核，输出一份带证据、可审计的研究解读。

**产品形态**：Windows 桌面应用（Electron + React 前端，Python 多 Agent 服务 sidecar，SQLite 本地存储）。

**核心价值主张（v0.2 修订）**：把「收到信号 → 逐票查资料 → 排除风险 → 形成结论」这一人工研究流程自动化，用三件事建立信任：**每维数据可溯源、关键数字由确定性代码计算、结论必须经过独立风险复核**。

> 这一章在回答：这是什么产品、给谁用的、和别人有什么不一样。面试中要求你用一句话说清产品，练的就是这一节。

### 1.1 定位修正记录（v0.1 → v0.2）

| | v0.1 假设 | 访谈结果 | v0.2 修正 |
|---|---|---|---|
| 首要卖点 | 本地优先 | 用户原话：「都无所谓」「不担心数据泄漏」 | 本地优先降级为工程实现方式，个人线不再作为卖点；机构线保留（未访谈，待验证） |
| 价值主张 | 证据可溯源（独占） | 东方财富妙想已宣称「全程 100% 溯源」 | 溯源保留为必要条件，但差异化改为：**报告级端到端自动化 + 确定性规则计算 + 数据源中立**（见竞品分析） |
| 人机关系 | 未定义 | 用户接受「人给方向 + AI 执行」，拒绝「AI 给方向」 | 新增产品原则：**AI 只做聚合与复核，不主动推荐标的、不生成研究主题** |

## 2. 背景与问题

> 这一章在回答：用户今天遇到了什么麻烦，为什么非做这个产品不可。素材来源应是用户访谈原话 + 工作流还原。

### 2.1 用户现状（2026-08-17 访谈还原）

受访者为信号驱动型量化研究者（PTrade 用户）：股票池约 1,000 只，行情正常时每天 3–5 只信号，行情向好时信号批量出现；采用 T+1 复盘模式，非盘中抢筹；单票研究 2–3 分钟，追求极致效率。

其处理信号是**高度标准化的 7 步工作流，全部在东方财富一个平台内完成**：

| 步骤 | 操作内容 | 平台 |
|------|---------|------|
| ① | 对信号股进行资金排序 | 东财 |
| ② | 打开多股同列，横向对比关键数据 | 东财 |
| ③ | 点击「大事」功能，快速排查重大利空 | 东财 |
| ④ | 查看全板块表现，确认所属板块环境 | 东财 |
| ⑤ | 查看某项特定的量化指标（策略核心依赖指标） | 东财 |
| ⑥ | 查看日 K 线走势，确认技术形态 | 东财 |
| ⑦ | 执行买入操作 | — |

数据维度**极度克制**：只看财报异常、前一日资金龙虎榜（全市场视角）、大事/股权穿透/细分概念、量化指标、日 K 形态；**明确不看**研报、评论区、技术指标。

同时存在**双轨工作流**：

1. **信号响应流**（核心）：盘中/T+1 快速决策，2–3 分钟/只，买/不买/观察。
2. **盘后研报流**（辅助）：每天读几十份研报并做笔记，用于积累认知与交叉验证（判断信号与盘后观点是否吻合、确认有无重大利空）。

**对 AI 的态度（原话摘录）**：
- 试过通义千问做研报总结，评价「只会讲好东西」「存在假信息」「搞错重点」——**完全不信任 AI 开放式内容生成**。
- 用 ChatGPT / Kimi 做量化方法论问答，「此类场景下 AI 回答有参考价值」——**接受结构化、可验证的问答**。
- 最担心 AI「造假 / 编造数据」，应对方式是「不信任即验证」；对漏风险容忍度较高（「有提醒最好，没有也无所谓」）。
- 信息需求：「现在也够了」——用户不追求「更多」，追求「更真」。

### 2.2 问题陈述（Problem Statement，v0.2 修订）

v0.1 假设「逐票人工查证耗时长（单份报告 30–60 分钟）」，**访谈证伪**：单票仅 2–3 分钟，用户已很快。真正的痛点不是慢，是**繁、漏、不敢**：

**对于** 每天处理 PTrade 信号的个人量化研究者（T+1 复盘型），
**他们的问题是** 单票研究不慢，但批量信号下 7 步重复操作繁重、人工逐票排查易遗漏关键利空、且 AI 工具不可信导致无法委托自动化，
**现有方案**（东方财富手工流程 / 通用大模型 / 金融数据终端）要么需要逐票手动操作，要么输出不可信、无法分辨预设外的量化信号，
**aquant 提供** 报告级端到端研究自动化：粘贴报告 → 解析 → 查证 → 风险复核 → 带证据的结论与极简决策卡片，
**核心差别在于** 每个结论都能追溯到来源，关键数字由代码而非模型决定，AI 只聚合不推荐。

### 2.3 访谈验证点回填（v0.1 假设 → 访谈结果）

| v0.1 假设 | 验证问题 | 访谈结果（原话/事实） | 结论 |
|---|---|---|---|
| 单份报告人工研究耗时 30–60 分钟 | 「哪一步最耗时？为什么慢？」 | 单票 2–3 分钟；7 步全在东财完成，无跨平台跳转；最耗时的「读研报」属于盘后独立工作流 | **证伪** → 价值主张从「省时间」转向「批量处理 + 不漏 + 可信」 |
| 用户最怕 AI 编数据，而非答得慢 | 「你最担心 AI 输出什么错误？」 | 最担心「造假 / 编造数据」；「不信任即验证」；对漏风险容忍度高 | **证实** → 证据溯源保留为核心机制 |
| 报告 30 分钟内生成才有用 | 「距离信号出现多久可接受？」 | T+1 复盘，盘中不急于响应，次日开盘前完成即可；对时效性要求极低 | **证伪（放宽）** → 业务 SLA 定为「信号产生后次一交易日开盘前」；工程目标 ≤10 分钟保留 |
| 用户愿意为「每月省 10 小时」付费 | 以 Wind 年费为锚点追问 | 不为数据工具付费；实际愿为博主知识付费 500–1,000 元/年；「若证明策略有效」3–5 万/年可接受 | **部分证伪** → 商业模式重写：定价锚定「效果证明」而非「省时间」（见第 10 章） |

### 2.4 访谈新增洞察 → 产品决策

| 洞察 | 访谈依据 | 产品决策 |
|---|---|---|
| 信息需求极度克制（5–6 维），拒绝信息过载 | Q6：不看研报/评论区/技术指标；「现在也够了」 | 新增**决策卡片**视图（FR-9），极简入口 + 按需展开证据详情；详细报告降级为二级视图 |
| 批量信号集中出现，等待出齐后统一处理 | Q2：行情向好时信号批量出现；Q4：择优挑选 | 新增**批量处理**需求（FR-11） |
| 有负面清单与观察池（延后决策） | Q8：信号逻辑相悖/大资金不持有/关键数据变差则放弃；数据变差放入观察池持续跟踪 | 新增**观察池**需求（FR-10） |
| 人给方向 + AI 执行 | Q9：AI「无法主动给出研究主题或方向」，需用户先给框架 | 产品原则：AI 不主动推荐标的、不生成研究主题 |
| 付费与「策略有效性证明」强绑定 | Q16：3–5 万/年「取决于策略有效程度」 | 新增**效果证明**机制（FR-12）：决策回填 + 命中率统计，作为高价付费的前提 |
| 平台极度单一（东财） | Q5：7 步全部在东财完成 | 竞品分析直面东方财富；决策卡片对齐 7 步心智、每维可跳转东财验证，降低迁移成本 |

## 3. 目标用户与使用场景

> 这一章在回答：为谁设计。画像要具体到能指导功能取舍，不是「喜欢用电脑的人」这种废话。

### 3.1 用户画像

**画像 A：个人量化研究者（种子用户，已访谈 1 人）**
- 信号驱动型，非主观选股；股票池约 1,000 只
- 每天 3–5 只信号（行情好时批量出现）；T+1 复盘，非盘中抢筹型
- 单票研究 2–3 分钟，7 步标准化工作流，全部在东方财富完成
- 工具链：PTrade（信号源）+ 东方财富（研究执行）+ ChatGPT/Kimi（方法论问答）
- 付费行为：不为 Wind/iFinD 等数据工具付费；愿为博主知识付费 500–1,000 元/年
- 特征：**对数据真实性敏感、有验证习惯、信息需求克制、信任「人的洞察」而非「工具的数据」**
- 待补充（第二轮访谈）：资金规模、信号优先级排序逻辑、第⑤步量化指标名称

**画像 B：机构量化研究员（未访谈，保留 v0.1 假设）**
- 券商/私募/资管，策略盘后跑批，报告进入晨会或投决流程
- 合规要求：资料可溯源、结论可复核、数据不可外传
- 现有工具：Wind/iFinD 付费终端 + 人工整理
- 特征：需要审计链，愿意为合规与效率付费（**待验证**，见第 11 章）

### 3.2 核心使用场景

| 场景 | 用户故事 |
|---|---|
| T+1 复盘研究 | 收盘后收到 3–5 只 PTrade 信号，粘贴进 aquant，得到带证据的研究解读、风险提示与多票对比决策卡片，次日开盘前完成决策 |
| 批量信号处理 | 行情向好、信号集中出现，一次性导入全部信号，批量生成卡片横向对比、择优处理（对应访谈「等待全部信号出齐后统一处理」） |
| 报告复核（机构） | 机构研究员将 aquant 输出作为初稿，人工仅复核风险项与未知项，而非从头查起 |
| 信号稳定性追踪 | 同一策略多日信号积累后，查看逐 Run 信号观察与稳定性统计，评估策略本身质量 |

### 3.3 非目标用户（首版不做）

- 盘中抢筹型、需要实时响应与秒级推送的交易者——访谈确认目标用户为 T+1 复盘型，「对时效性要求极低」
- 纯主观交易、不看量化报告的散户——无对应场景
- 期望 AI 主动推荐标的、给研究方向的用户——访谈明确拒绝「AI 给方向」，与本产品原则冲突

## 4. 竞品分析（摘要）

> 这一章在回答：市场上已有替代方案，为什么用户不继续用它们。结论必须落到「我们的差异化」。
> 完整版见 [COMPETITIVE_ANALYSIS.md](./COMPETITIVE_ANALYSIS.md)，本节仅保留结论性矩阵。

### 4.1 替代方案矩阵（v0.2 更新）

| 类别 | 代表 | 优势 | 与 aquant 的差距 |
|---|---|---|---|
| 用户现状：东财手工流程 | 东方财富（免费功能） | 免费、一站式、用户习惯（7 步全部可完成） | 7 步全手动、逐票重复；多股对比靠手动切换；无 AI 解释信号 |
| 行情终端内置 AI | 东方财富妙想（投研助理/Skills/六大技能）、同花顺问财 | 数据+语料+账户闭环；妙想宣称「全程 100% 溯源」 | 不解析 PTrade 报告；无用户自身策略信号规则的确定性计算；数据绑定单一平台；云端处理 |
| 金融数据终端 | Wind / iFinD / Choice | 数据全、权威、成体系 | 只提供数据不提供结论；贵；访谈确认目标用户不为数据工具付费 |
| AI 投研产品 | 慧博（研报问答/智能策略终端） | 1,800 万份研报语料、接入 DeepSeek、机构服务能力 | 以研报为中心，非信号复盘工作流；个人线产品弱 |
| 通用大模型 | ChatGPT / Claude / Kimi / 通义千问 | 上手零成本、通用性强 | 无信号解析；研报总结场景已被用户否定（通义千问：假信息、抓不住重点）；幻觉无约束 |

### 4.2 差异化结论（v0.2 修订）

v0.1 的「本地优先 + 可审计证据 + 确定性计算层」三词定位，访谈与竞品调研后修正为：

**报告级端到端自动化 + 确定性规则计算 + 数据源中立 + 人机协作边界**

- 妙想/问财没有的：粘贴 PTrade 报告直达结论的端到端工作流；用户自身策略信号规则的确定性判定（代码不算错）
- 数据终端没有的：从报告到结论的自动化，而非只给数据
- 东财生态没有的：数据源中立（Tushare/巨潮/东财公共查询/Tavily 多源整合），不绑定单一平台
- 通用大模型没有的：证据强制登记、独立风险复核、失败回退到确定性结果
- 用户心智上独有的：**AI 只聚合不推荐**——尊重「人给方向、AI 执行」的协作模式

## 5. 产品目标与成功指标

> 这一章在回答：做成什么样算成功。北极星指标只有一个，护栏指标防止为冲指标牺牲质量。

### 5.1 北极星指标（North Star Metric）

**可信研究完成次数（周）**——用户粘贴报告并完成一次带证据、含风险复核的研究解读。它同时刻画了使用频率与信任建立，两个维度缺一不可。
（访谈校准：种子用户每周 3–5 只信号，该指标天然有限，因此配套过程指标「信号覆盖率」= 完成研究的信号数 / 用户当周信号总数。）

### 5.2 护栏指标（Guardrail Metrics）

| 指标 | 定义 | 目标 |
|---|---|---|
| 幻觉率 | 结论中无法溯源到登记 Evidence 的事实占比 | < 1%（需黄金评测集，见 9.2） |
| 溯源覆盖率 | 决策卡片/结论中每维数据可跳转来源的比例 | 100%（访谈 Q12：突破信任门槛的关键是「每维数据可溯源、可验证」） |
| 证据缺失率 | 用户本可查到、但输出标为「未知」的关键项占比 | 逐月下降 |
| 端到端时长 | 粘贴报告 → 最终综合的耗时 | 工程目标 ≤ 10 分钟；业务 SLA：信号产生后**次一交易日开盘前**（访谈放宽） |
| 批量模式单票耗时 | 批量处理下平均单票耗时 | ≤ 人工基线（2–3 分钟/票），用于效果沟通 |
| 单次成本 | 一次完整 Run 的模型 Token 成本 | 控制在订阅定价的可覆盖范围内 |
| 模型回退率 | 模型输出校验失败、回退确定性能力的比例 | < 5% |

### 5.3 过程指标（当前阶段）

- 种子用户周活跃率、重跑率（同一报告重新运行代表用户在验证或对比）
- 风险复核后用户主动取消研究的比例（越低说明初轮质量越可信）
- 决策卡片三态分布（通过/放弃/观察）与采纳率——验证卡片结论是否与用户真实决策一致
- 观察池活跃度：从观察池重新发起研究的比例

## 6. 产品范围

> 这一章在回答：这一版做什么、不做什么。PRD 里「不做什么」和「做什么」同等重要——它是 PM 做的取舍。

### 6.1 范围内（In Scope）

- v0.1 桌面纵向切片（已实现）：解析 → 编排 → 专家 → 风险复核 → 综合 → 运行记录 → 配置治理 → 密钥管理（见第 7 章 FR-1 ~ FR-8）
- v0.2 新增（访谈驱动，规划中）：决策卡片（FR-9）、观察池（FR-10）、批量处理（FR-11）、效果证明回填（FR-12）

### 6.2 范围外（Out of Scope，首版明确不做）

- **不连接任何交易接口**——输出仅是研究解读与风险提示，不构成买卖建议，未来任何写操作必须另设人工批准边界
- **不做盘中实时信号推送**——访谈确认 T+1 复盘模式，时效要求极低，实时性不是卖点
- **不做 AI 主动推荐标的 / 生成研究主题**——访谈明确拒绝「AI 给方向」
- **不做 AI 研报观点总结**——用户已否定通义千问的研报总结（假信息、抓不住重点）；未来若做，仅做证据化抽取（数据/大事/概念 + 原文链接），不生成观点
- 不连接旧服务器、邮箱等历史数据源
- 不支持多用户协作、团队评论、审批流（列入 P1/P2 路线）
- 不支持 Web/移动端（桌面优先）
- 自动交易、组合管理、绩效归因

> 面试常见追问：「为什么不做交易执行？」标准答案：信任未建立前做交易等于把未经验证的 AI 输出直接作用于资金，风险不可控；且写操作意味着全新安全与合规责任，需人工批准边界。这是 PM 的边界意识。

## 7. 功能需求

> 这一章是 PRD 的主体，回答：产品具体长什么样、每个功能怎么验收。
> 写法要点：**按用户旅程组织**（不是按技术模块），每个需求带验收标准，功能点写「规则」而非「实现」。
> FR-1 ~ FR-8 为 v0.1 已实现；FR-9 ~ FR-12 为访谈驱动的 v0.2 新增（标注「规划中」）。

### 7.1 报告导入与解析（FR-1）

用户将 PTrade 原始文本粘贴进应用，系统确定性解析（非模型解析）为结构化报告。

- FR-1.1 解析状态三分：`valid` 可直接运行；`partial` 需人工确认缺失字段后运行；`invalid` 阻止启动并说明原因
- FR-1.2 解析结果先展示确认预览，用户确认后才可启动研究
- FR-1.3 量化正式池与 P1/P2/P3 候选池由确定性规则计算，模型不可修改名单、排序与数字

**验收标准**：粘贴一份字段缺失的 PTrade 报告 → 系统标记 `partial` 并列出缺失项 → 用户确认后运行；粘贴非报告文本 → 阻止启动并给出原因。

### 7.2 多 Agent 研究编排（FR-2）

确认后，统筹 Agent 根据报告内容与当前启用的能力注册表动态选择专家并派发任务；专家并行执行。

- FR-2.1 默认五个 Agent：统筹、量化信号、公司与行业、外围市场、风险
- FR-2.2 量化信号与风险为**核心治理角色，不可停用**；公司与行业、外围市场可按项目启停
- FR-2.3 统筹只能从已注册且启用的 Agent 中派单，不允许模型创造新角色
- FR-2.4 相同 Agent + 标的 + 问题的任务不重复派发；追问轮次共享 `max_rounds` 上限，保证运行必然结束
- FR-2.5 专家返回后统筹主动审阅：发现事实矛盾、重大信息或证据缺口时，携带具体问题再次调用现有 Agent

**验收标准**：同一报告连续运行两次，第一次发现的证据缺口在第二次被追问补查；运行在 `max_rounds` 内必然终止（completed / failed / cancelled 之一）。

### 7.3 专家能力（FR-3）

**量化信号 Agent**
- FR-3.1 证券稳定 ID 与名称历史（支持改名/退市识别）
- FR-3.2 PTrade 确定性规则计算：正式观察只接受 `all_conditions_met`；near 标的按 P1/P2/P3 确定性归类
- FR-3.3 逐 Run 信号观察记录与稳定性统计

**公司与行业 Agent**
- FR-3.4 接入 Tushare（股票身份、行业、公司信息、估值、财务指标、业绩预告）、巨潮公告、东方财富新闻与研报；Tavily 补充行业资料
- FR-3.5 各数据源允许部分成功，失败项逐条进入 `unknowns`，不补写事实

**外围市场 Agent**
- FR-3.6 以 A 股报告日为锚点：美股取严格早于报告日的最近交易日，韩股取不晚于报告日的最近交易日；休市自动回退
- FR-3.7 固定展示五个核心指数，标准化涨跌并生成五日折线图；行情失败时仅展示醒目标注的 demo 数据

**风险 Agent**
- FR-3.8 逐票检索报告日前的潜在利空（公告、处罚、异动等），置于专业分析之后独立执行
- FR-3.9 风险汇总后统筹再次审阅，才进入最终综合

**验收标准**：构造一份含改名标的、缺失 Tushare 权限字段、美股休市日的报告 → 三个 Agent 分别正确输出身份历史、unknowns 清单、回退后的交易日口径。

### 7.4 证据登记与引用约束（FR-4）

- FR-4.1 所有外部事实必须关联 Evidence ID，含来源类型、标题、URL、摘要、发布日期、检索时间与关联标的
- FR-4.2 统筹模型只能引用已登记的证据，不能凭空引用
- FR-4.3 模型输出必须通过结构化校验；失败、越权或缺少必需字段时自动回退到确定性结果，并产生 `model.fallback` 事件
- FR-4.4 量化事实由确定性代码计算，模型不能覆盖解析结果

**验收标准**：最终综合中的每一条外部事实均可点击跳转到来源；人为制造模型输出缺字段 → 系统回退并在运行记录中可见 `model.fallback`。

### 7.5 最终综合输出（FR-5）

- FR-5.1 输出研究解读与风险提示两部分；明确声明不构成买卖建议
- FR-5.2 每个 Agent 统一交付八项：做了什么、得到什么事实、使用了哪些 Evidence、存在哪些风险、哪些未知、是否需补查、Prompt/模型/工作流版本、耗时与成本

### 7.6 运行记录（FR-6）

- FR-6.1 查看历史 Run 全量事件（按 `run_id + seq` 有序重放）
- FR-6.2 每个 Run 展示耗时、参与 Agent、证据、风险、Token、回退与错误指标
- FR-6.3 一键重跑（复用已确认报告、新建 Run，保留可比较的审计轨迹）；Markdown 导出

### 7.7 Agent 管理与 Prompt 工作台（FR-7）

- FR-7.1 可选 Agent 启停、项目级附加要求；每次保存递增配置版本，新 Run 使用最新版本
- FR-7.2 Prompt 工作台：查看完整系统 Prompt、草稿、发布、历史版本、回滚；平台安全策略只读
- FR-7.3 草稿不影响运行；发布只影响之后的 Run；回滚以新建版本完成，不篡改旧版本
- FR-7.4 附加要求可以约束任务上下文，但不能扩大工具白名单，不能覆盖确定性规则

### 7.8 连接与密钥（FR-8）

- FR-8.1 应用内配置统筹模型（OpenAI-compatible）、Tushare token、Tavily key，均可「保存并测试」
- FR-8.2 未配置统筹模型时自动使用本地回退能力，产品仍可用
- FR-8.3 密钥用 Windows DPAPI 当前用户作用域加密存储；界面与协议只返回「是否已配置」，永不回显明文

### 7.9 决策卡片（FR-9，v0.2 P0 新增，规划中）

> 访谈驱动来源：用户 7 步工作流（Q5）+ 信息需求克制（Q6「现在也够了」）+ 溯源诉求（Q12「每维数据可溯源、可验证」）+ 批量对比（Q4「多股同列」）。这是访谈 P0 机会点「信号决策助手」的落地形态。

- FR-9.1 每只信号标的生成一张极简决策卡片，固定六维：
  ① 资金流（前一日龙虎榜全市场视角 + 资金排序）
  ② 大事利空排查（重大公告/处罚/异动）
  ③ 板块环境（所属板块当日表现）
  ④ 量化指标核验（信号规则确定性计算通过与否）
  ⑤ 日 K 形态
  ⑥ 财报异常
  每维带来源链接可跳转验证；缺失标「未找到」，不编造（映射访谈 Q12 信任门槛）
- FR-9.2 卡片结论三态提示：**通过 / 放弃 / 观察**。放弃条件由确定性规则 + 证据给出（信号逻辑相悖、大资金不持有或流出、关键数据变差——映射访谈 Q8 负面清单）；**最终决策由人做出**，卡片不代替决策
- FR-9.3 多票同列对比视图：批量信号的卡片横向排列，支持按维度排序（映射访谈 Q5 步骤① ②）
- FR-9.4 极简优先：卡片为默认入口，详细研究解读与 Agent 明细为二级视图，按需展开（拒绝信息过载，映射访谈 Q6）

**验收标准**：导入含 3–5 只标的的报告 → 每票生成六维齐备、可溯源的卡片；构造含重大利空的标的 → 卡片三态提示为「放弃」并给出证据链接；点击任一维度 → 跳转来源页面或展开证据详情。

### 7.10 观察池（FR-10，v0.2 P1，规划中）

> 访谈驱动来源：Q8——因数据变差而暂停的标的放入观察池持续跟踪，而非彻底删除（「延后决策」场景）。

- FR-10.1 用户可将卡片标记为「观察」，标的进入观察池
- FR-10.2 观察池标的在后续 Run 中自动比对关键数据变化，出现恶化时提示（对应「关键数据变差」放弃条件）
- FR-10.3 支持从观察池一键重新发起完整研究

**验收标准**：标记观察 → 下一 Run 该标的出现数据变化提示；从观察池重跑生成新卡片。

### 7.11 批量处理（FR-11，v0.2 P1，规划中）

> 访谈驱动来源：Q2/Q4——行情向好时信号批量出现，用户等待全部出齐后统一处理、择优挑选。

- FR-11.1 多份报告或批量信号一次性导入，队列处理，统一输出决策卡片列表
- FR-11.2 批量模式单票平均耗时目标 ≤ 人工基线（2–3 分钟/票），作为效果沟通的关键数字

**验收标准**：10 只信号批量导入 → 全部生成卡片；批量模式平均单票耗时显著低于 10 × 2.5 分钟人工基线。

### 7.12 效果证明回填（FR-12，v0.2 P1，规划中）

> 访谈驱动来源：Q16——付费意愿与「策略有效性证明」强绑定（「取决于策略有效程度」）。这是高价付费的前提，先于商业化设计。

- FR-12.1 用户轻量回填最终决策（买/不买/观察）与后续结果，系统统计信号 → 决策 → 结果的命中率与时间节省
- FR-12.2 周期性输出策略有效性报告：信号命中率、观察池转化、累计节省时间
- FR-12.3 回填交互必须极轻（一次点击 + 可选备注），不增加研究负担（用户单票仅 2–3 分钟）

**验收标准**：累计 20 次回填后生成第一份有效性报告，含命中率与对比基线；单次回填交互 ≤ 10 秒。

## 8. 非功能需求

> 这一章在回答：除了功能，产品还必须保证什么——性能、安全、隐私、合规。对 AI 产品，安全与隐私是核心卖点而非附属项。

### 8.1 安全与隐私

- 报告数据不出本机：首版只读取用户粘贴的报告，不连接旧服务器、邮箱或交易接口
- Renderer 无 Node 权限，仅经 context-isolated preload 调用白名单 IPC；启用 sandbox 与 CSP；外链只允许无凭据 HTTPS
- Python Harness 不向 Agent 开放 shell、文件写入、任意 Python 或下单工具
- 隐藏思维链不保存；只保存结论、结构化详情、任务、状态与错误
- 密钥不写入日志、聊天事件或导出包

> 访谈校准（Q13/Q14）：个人用户对数据本地化「都无所谓」，不担心泄漏。因此**本地优先保留为实现方式（成本低、架构已如此），但不再作为个人线营销卖点**；机构线（画像 B）仍以本地化为卖点，待访谈验证。

### 8.2 可靠性与边界保证

- 每次运行有预算、轮数上限，保证终止
- 外部查询失败或权限不足时逐项标为未知，不编造
- 支持暂停、取消与节点边界插话

### 8.3 合规

- 输出定位为研究解读与风险提示，显式声明不构成投资建议
- 数据源使用遵守各平台条款（只读、限时、公共查询）

### 8.4 性能目标（v0.2 更新）

| 项 | 目标 |
|---|---|
| 端到端时长 | 工程目标 ≤ 10 分钟；业务 SLA：信号产生后次一交易日开盘前（访谈放宽，见 2.3） |
| 批量模式单票耗时 | ≤ 人工基线 2–3 分钟/票（效果沟通关键数字） |
| 应用冷启动 | ≤ 5 秒 |
| 历史 Run 事件重放 | 1000 条事件内滚动流畅 |

## 10. 商业模式（v0.2 重写）

> 这一章在回答：谁付钱、为什么付、怎么定价。面试项目中哪怕没有收入，也要有一个思考过的结构。
> 本版依据访谈实际付费行为与付费意愿重写（v0.1 的「月费 50–100 元」假设已被访谈数据替代）。

### 10.1 访谈付费数据（定价的事实基础）

| 事实 | 出处 | 含义 |
|---|---|---|
| 不为 Wind/iFinD 等数据工具付费 | Q10 | 「工具的数据」没有付费心智 |
| 愿为博主知识付费 500–1,000 元/年（付费社群） | Q10 | 实际付费行为锚点：认可「人的洞察」 |
| 「若每月省 10 小时」语境下 3–5 万/年可接受，前提是策略有效 | Q16 | 付费上限由**效果证明**决定；但注意该问题预设的「省 10 小时」与用户实际耗时（每天约 10–15 分钟）不匹配，数字不可直接用于定价 |

### 10.2 定价结构（假设，待阶段二访谈验证）

| 档位 | 对象 | 形态 | 定价假设 | 依据 |
|---|---|---|---|---|
| 免费版 | 画像 A | 统筹 + 量化信号（核心信任链） | 0 | 先建立「不造假、可溯源」认知，才谈得上付费（访谈 Q12：信任是门槛） |
| 个人订阅版 | 画像 A | 决策卡片 + 公司与行业 + 风险复核 + 外围市场 + 观察池 | **年费 499–999 元**，锚定用户实际付费行为（博主知识付费价位） | Q10：这是用户真实掏过钱的价位带 |
| 个人高阶版 | 画像 A（重仓/小团队） | 效果证明报告（FR-12）+ 策略诊断 + 自定义工作流 | 年费万级，对标 Wind 3–5 万打 3–5 折 | Q16：效果证明成立后才解锁此档 |
| 机构线 | 画像 B | 本地/私有化部署 + 年费，含 SSO、审计、评测报告 | 以 Wind 终端年费为对标，打 3–5 折 | 保留 v0.1 假设，未访谈 |

**转化逻辑**：免费（建立可信认知）→ 订阅（效率 + 可信 + 批量）→ 高阶（效果证明）。高价档不是促销来的，是 FR-12 数据证明出来的。

**待验证**：阶段二访谈第 27 问（体验后付费意愿与免费版构成）。

## 11. 开放问题（Open Questions）

> PRD 一定有不完备之处。诚实列出开放问题，比假装全想清楚了更专业。

1. **第二轮访谈待确认**（访谈记录第五节）：第⑤步「某项特定量化指标」的名称与类型——决策卡片第④维是否覆盖它，直接决定产品可用性；信号是否有优先级/强弱排序及排序逻辑；观察池的重新评估机制。
2. **效果证明的归因**：命中率提升归因于策略还是工具？每天 3–5 只信号的样本量，需要多少周才能得到有说服力的统计（涉及 FR-12 的统计设计）。
3. **竞争回应**：东方财富妙想已宣称「100% 溯源」，是否需要产品侧动作（如独立评测、溯源能力对比）？（见竞品分析第 7 节）
4. **盘后研报流是否立项**：用户已否定 AI 观点总结；「证据化抽取」形态是否被接受，还是盘后流保持纯人工？
5. 免费版只留「统筹 + 量化」是否足以让用户感知价值并转化？（阶段二访谈第 27 问验证）
6. 机构线先做私有化交付还是先做 SaaS 多租户？（取决于早期客户，P1 再定）
7. 画像 A 的资金规模、信号优先级排序逻辑缺失（第二轮访谈回填）。
