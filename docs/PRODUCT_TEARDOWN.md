## 1. 产品是什么

**一句话**：aquant 把「收到量化信号后那 2–3 分钟的 7 步手工查证」变成「一次粘贴 + 一次确认」——用户把 PTrade 量化报告交给它，多个 AI 研究员分工查证、交叉复核，输出一份带证据、可逐条验证的研究解读。

**产品形态**：本地优先的桌面应用（另有云端 Web 版），原创「墨研 · 中式研房」视觉风格。

**一句话差异化（面试用）**：「妙想和问财帮用户选股，aquant 帮用户**复盘**股——把 7 步手工操作变成一次粘贴，每一步都能点开来源验证。AI 在这里只负责聚合证据，不负责给方向。」

## 2. 需求怎么来的：一场访谈推翻了 3/4 的假设

产品的起点不是「我想做个多 Agent 应用」，而是一条标准的需求发现路径：**写假设 → 访谈真实用户 → 假设被证实/证伪 → 回填 PRD**。

### 2.1 用户是谁、在干什么

访谈对象（2026-08-17，28 分钟，PTrade 个人量化研究者）：

- 信号驱动型策略，股票池约 1,000 只，行情好时信号批量出现
- **T+1 复盘**：盘中不抢，次日开盘前完成研究即可
- 单票研究 2–3 分钟，一套**高度标准化的 7 步工作流，全部在东方财富完成**：资金排序 → 多股同列 → 「大事」查利空 → 看板块 → 查某个特定量化指标 → 看日 K → 买入
- 对 AI 的态度极其鲜明：试过通义千问做研报总结，评价「只会讲好东西」「假信息」「搞错重点」——**完全不信任 AI 开放式内容生成**；但接受「结构化、可验证的问答」

### 2.2 四个假设，三个被推翻

| v0.1 假设 | 访谈结果 | 设计影响 |
|---|---|---|
| 单份报告人工研究 30–60 分钟（痛点=慢） | 单票只要 2–3 分钟，7 步全在东财 | **证伪** → 卖点从「省时间」改为「批量 + 不漏 + 可信」 |
| 本地优先是核心卖点 | 「都无所谓」「不担心数据泄漏」 | **证伪** → 本地化降级为交付方式，机构线保留为卖点 |
| 报告 30 分钟内生成才有用 | T+1 复盘，次日开盘前即可 | **证伪（放宽）** → 时效不敏感，可信度才是全部 |
| 用户愿为省时间付费 | 不为 Wind 付费；愿为博主知识付费 500–1000 元/年；「若证明策略有效」3–5 万/年可接受 | **部分证伪** → 定价锚定真实付费行为，「效果证明」解锁高价 |

### 2.3 真正的痛点：繁、漏、不敢

访谈证伪了「慢」之后，痛点被重新定义为三个字：

- **繁**：批量信号下 7 步操作逐票重复（用户会「等全部信号出齐后统一处理」）
- **漏**：人工逐票排查易漏掉关键利空（用户有明确的负面清单：信号逻辑相悖、大资金不持有、关键数据变差 → 放弃）
- **不敢**：AI 工具不可信，导致「查证」这件事根本无法委托自动化

配套的关键洞察：用户信息需求**极度克制**——明确不看研报、评论区、技术指标；「现在也够了」；**不追求更多，追求更真**。以及人机关系上，用户接受「人给方向 + AI 执行」，明确拒绝「AI 给方向」（AI 无法主动给出研究主题，需要人先给框架）。

> 这一段是面试必讲的：产品的整个形状不是设计出来的，是从这 28 分钟访谈里**倒推**出来的。

## 3. 三条产品原则：一切设计的总纲

访谈结束后，所有后续设计都收敛到三条原则。本文档第 4–6 节每个决策都能回溯到这三条。

### 原则一：人给方向，AI 执行

**出处**：Q9「AI 无法主动给出研究主题或方向」；Q4/Q5 用户工作流的方向从来由信号（人）给。

**推论**：
- 产品不做选股、不荐股、不生成研究主题——入口永远是用户粘贴的报告
- 运行中用户随时可以暂停、取消、插话补充指令（在节点边界交给统筹）
- 启动研究前必须人工确认解析结果——「跑不跑」的决定权在人
- 最终卡片只反映用户策略规则的执行结果，AI 不添加自己的「推荐」

### 原则二：不装懂

**出处**：Q11 最担心「造假 / 编造数据」，「不信任即验证」；Q7 通义千问「只会讲好东西」「假信息」；Q12「每维数据可溯源、可验证」是信任门槛。

**推论**：
- 查不到就标「未知」，缺失不补零、不默认通过——绝不编造
- 每一条外部事实挂证据链接，可点击跳转验证
- 风险检索不到时明说「本轮未检索到明确利空，**但不等于公司没有风险**」
- 行情源降级为演示数据时必须醒目标注，不与真实数据混同
- 模型输出不合格时回退到程序生成的结果——宁可朴素，不可失真

### 原则三：克制（追求「更真」而非「更多」）

**出处**：Q6 信息需求极度克制、拒绝信息过载；Q12「现在也够了」。

**推论**：
- 输出默认是极简的决策卡片，详细解读降级为二级视图
- 统筹审阅默认不追问——「普通字段缺失记录为未知，不要为追求完整而反复追问」（这是直接写进审阅规则的）
- 不做 AI 研报观点总结（用户已用通义千问实测否定），若做盘后研报流，只做「证据化抽取」不给观点

## 4. 每个子 Agent 的设计档案

### 4.1 统筹 Agent —— 用户本人是「编排者」，产品把它自动化了

**需求怎么来的**：用户的 7 步工作流本质上是一个编排流程——先看什么、后看什么、哪些结果要交叉验证。此前编排者是用户本人。同时 Q7 证明「让 AI 直接总结」会抓不住重点（通义千问失败案例），所以不能一步到位地「报告进来、结论出去」，必须是**先分工、再执行、再复核、再综合**的流程，每一步都有检查点。

**为什么这么设计**：
- **组队受约束**：统筹只能从已启用的能力池里选人，不能发明新角色——防止 AI 为了「显得能干」编出虚构的专家
- **审阅要克制**：统筹在专家返回后要审阅（查矛盾、查证据缺口），但**默认结论是「不用追问」**——只有问题会「实质改变核心结论」时才允许追加一轮。这条规则直接映射访谈 Q12「用户不追求更多」
- **追问有预算**：追问轮数有硬上限，保证流程必然结束，不会陷入 AI 式无限循环

### 4.2 量化信号 Agent —— 策略规则的「忠实执行者」

**需求怎么来的**：Q5 第⑤步「查看某项特定的量化指标（策略核心依赖指标）」是用户 7 步里最策略相关的一步；Q3 用户「对 PTrade 信号数据不存疑，直接采信」。也就是说：**信号数据是用户信任的锚点，任何解释都必须忠实于上游数据，不能经过 AI 二次加工**。

**为什么这么设计**：
- 正式池与 P1/P2/P3 候选分层的判定**全部由程序规则计算**（资金公式、量比区间、换手区间、内外盘、结构异常），AI 只负责把结果翻译成人话
- **P1/P2/P3 怎么来的**：Q4 用户「择优挑选」+ Q8 负面清单「关键数据变差 → 放弃或观察」——用户需要知道「差一点的票差在哪里」，所以候选要分层、每层写明缺哪一条。诚实分层 = 原则二的直接落地
- **稳定性记忆怎么来的**：Q16 付费意愿取决于「策略有效程度」→ 效果证明机制（FR-12）需要跨多次运行积累每只票的历史表现 → 稳定性记忆就是效果证明的数据底座。一条从「付费意愿」一路追到「信号观察记录」的需求链

### 4.3 公司与行业 Agent —— 信息范围被访谈明确划定了

**需求怎么来的**：Q6 用户会看「财报异常、大事/股权穿透/细分概念」——这些是信号之外的公司层面背景查证。

**为什么这么设计**：
- **明确不做什么**：Q6 用户明确不看研报、评论、技术指标 → 该 Agent 只做证据化资料收集（公告、新闻、财报、行业资料），不做观点生成
- **多源交叉**：竞品分析的结论「数据源中立」——用户 7 步全在东财，aquant 的价值在于提供东财生态里没有的交叉验证（官方公告、独立数据源），而不是再造一个东财

### 4.4 外围市场 Agent —— T+1 复盘的时间差

**需求怎么来的**：Q2/Q15 确认 T+1 复盘、次日开盘前决策——**决策时点与信号时点之间隔着一夜**，隔夜美股/韩日市场的走势是开盘背景。Q4 用户「看行情判断时机，结合大盘环境灵活调整」佐证了「大盘环境」是决策维度之一。

**为什么这么设计**：
- 以 A 股报告日为锚：美股取严格早于报告日的最近交易日，韩日取不晚于——**不取报告日之后的数据，避免「用未来信息解释过去」**
- 行情源失败时展示醒目标注的演示数据——原则二（不装懂）在数据层面的表达

### 4.5 风险 Agent —— 对抗「AI 只会讲好东西」

**需求怎么来的**：Q8 用户的负面清单（信号逻辑相悖 / 大资金不持有 / 关键数据变差 → 放弃）；Q7 通义千问「只会讲好东西」——**专业分析天然有「找亮点」的偏置**，如果利空检索混在查证流程里，很容易被稀释。

**为什么这么设计**：
- **独立成一个 Agent、且放在专业分析之后**——专门、对抗性地逐票检索利空，不承担「讲好公司」的职责
- 只检索报告日之前的资料、每票有数量上限、摘要不足时明说「需打开原文核验」而不是升级为已确认风险
- 检索不到时写「未检索到明确利空，但不等于没有风险」——不装懂的句式设计
- 竞品层面，这正是差异化「帮你确认没有漏掉利空」的故事：不打「更多信息」，打「不漏」（竞品分析第 7 节）

## 5. 核心抉择：为什么子 Agent 是「固定流程 + 模型解释」，而不是 LLM 自主思考

这是整个产品最核心的设计判断，面试几乎必被追问。答案是**从用户的信任结构倒推出来的**：

### 5.1 用户不信任「模型自由生成的内容」，只信任「可验证的结果」

访谈 Q11 用户最怕造假，Q12 给出的信任门槛是「每维数据可溯源、可验证」。注意这个门槛的隐藏含义：**要可验证，产出过程就必须是可审计的**。一个固定流程里，每一步（解析了什么、查了什么、怎么判定的）都有明确记录、可以回放；而 LLM 自主思考是黑盒，用户无从验证它「想」了什么。所以：**凡是用户要拿去决策的关键环节——信号判定、名单、排序、数字、利空筛选——必须由程序规则执行，模型只能解释，不能决定。**

### 5.2 「代码不算错」是模型无关的护城河

竞品分析里识别到：妙想、问财的「AI 选股/解读」本质是 LLM 推理。大模型能力再进化，「推理」和「执行规则」之间仍有本质区别——**代码判定永远不会幻觉**。aquant 的确定性规则计算（正式池 / P1/P2/P3 分层）是「模型无关的护城河」：这是巨头在 LLM 能力上碾压你也没法通过堆模型追平的差异。

### 5.3 模型降级为「增强层」，产品在没有模型时依然成立

把核心链路做成确定性流程，意味着「没配置模型」时产品依然能交付核心价值（程序照样算分层、照样检索利空、照样出卡片）。这不是技术余量，是**产品信任建立路径**：商业模式里免费版 = 统筹 + 量化信号——恰好是完全确定性的部分。用户可以先用零成本验证「这个工具不造假」，再决定是否接入模型换取更好的解读体验。信任先行，付费在后。

### 5.4 但 LLM 并非被排除——边界很清楚

模型被用在三个「锦上添花且失败无害」的地方：
1. **通俗解释**：把程序结果翻译成普通投资者能读懂的说明（用户不懂字段缩写）
2. **消息面压缩**：把查到的公告/新闻压成每票最多两条的摘要
3. **审阅判断**：识别不同专家结果之间的矛盾与证据缺口，决定要不要追问

这三处共同点：输出不进入决策关键路径、失败时有无损兜底（程序版结果直接顶上）。

### 5.5 一句话总结（背下来）

> **确定性决定「结论对不对」，模型决定「话好不好懂」。把信任最敏感的部分留在代码里，把语言最擅长的部分交给模型——这就是「什么交给代码、什么交给模型」的边界。**

## 6. 关键产品决策速查（10 个「为什么」）

| # | 决策 | 为什么这么做 | 出处 |
|---|---|---|---|
| 1 | 解析后先预览、`partial` 必须人工确认才能启动 | 缺失字段要人知情（不装懂）；「跑不跑」的决定权在人（人给方向）；按钮文案「确认风险并启动研究」本身就是提示 | 原则一、二 |
| 2 | 运行中支持暂停 / 取消 / 插话 | 「人给方向、AI 执行」的操作化——方向错了人要能随时纠偏，插话在节点边界交给统筹而不是打断半截的查询 | 原则一 |
| 3 | 输出是「规则推荐卡片」而非长报告 | 卡片只含程序判定通过的票（AI 不推荐）；逐票消息面 + 风险最多两条（克制）；详细解读降级二级视图；卡片六维刻意对齐东财 7 步心智，每维可跳转东财验证——**降低迁移成本，嵌入用户已有验证习惯而非要求用户放弃东财** | Q6、Q12、竞品分析第 7 节 |
| 4 | 做邮件摄入链路（PTrade → 邮箱 → 自动收报告） | 上游 PTrade 平台原生能力就是定时发邮件，用它接入信号**不需要券商 API 权限、不碰交易接口、不改用户上游习惯**——迁移成本最低的信号接入方式；且只在用户点「查询最新邮件」时拉取，不常驻——产品克制 | 原则三 |
| 5 | 运行记录 + 一键重跑 + 导出 | 「可验证」是信任门槛，历史记录就是验证的入口；重跑生成新记录、不覆盖旧记录——支持「同一报告换配置/换 Prompt 版本对比」，也是效果证明（FR-12）与评测意识的数据基础 | Q12、Q16 |
| 6 | Agent 管理与 Prompt 工作台（启停、附加要求、草稿→发布→回滚） | 画像 B（机构研究员）不同项目有不同附加要求；金融场景天然要求「版本可追溯」；边界设计：附加要求可以约束任务内容，但**不能扩大工具权限、不能覆盖确定性规则**——治理边界与功能灵活性共存 | 画像 B、原则二 |
| 7 | 核心三 Agent（统筹/量化/风险）不可停用 | 量化执行用户的策略规则、风险提供对抗复核——这两者构成「可信」的承诺本体，停用了产品主张就不成立；公司行业/外围市场可按需启停 | 原则二 |
| 8 | Web 版配置只读 + 每日额度 + 口令门 | 多访客演示环境的防破坏：一个访客改坏 Prompt 会影响之后所有人；额度与并发上限是「产品限制跟随资源约束」的诚实设计；会话隔离（看不到别人的运行） | 产品化意识 |
| 9 | 「墨研 · 中式研房」原创视觉 | 面试演示项目需要记忆点；明确要求不模仿流行产品风格；中式研房与「研究室」的品牌叙事一致 | 设计偏好 |
| 10 | 先做桌面版，后补 Web 版 | MVP 原则：单用户场景桌面形态最快验证（便携包发给种子用户零门槛）；Web 版第二阶段为「演示与多访客」而生，而非功能扩展 | LAUNCH_PLAN |

## 8. 三条产品链路（产品视角）

不再讲技术，只讲「这条链路为什么存在、解决了什么」：

### 链路 1：桌面版（种子用户的交付形态）

**为什么**：目标用户是个人研究者、单机场景；本地运行 + 便携包分发，让种子用户拿到就能用（LAUNCH_PLAN 的 4–8 周验证依赖这个）。「本地优先」在访谈中被证伪为卖点，但作为**交付方式**保留——成本低、不依赖服务器。

### 链路 2：Web 云端版（演示与多访客形态）

**为什么**：面试演示和外部体验需要「打开链接就能用」；从单用户到多访客，暴露并解决了三个真实产品问题——访问控制（口令门）、防破坏（配置只读、每日额度、并发上限）、数据隔离（各看各的运行）。**这条链路的价值不只是「多了一种形态」，而是产品从个人工具向多用户产品迈了一步。**

### 链路 3：邮件摄入（信号源接入）

**为什么**：核心体验是「收到信号 → 研究」，粘贴仍有摩擦。借助上游 PTrade 平台原生发邮件的能力，把信号源直接接进产品——不改用户上游习惯、不碰交易接口，是**迁移成本最低的闭环**。设计上坚持「按需拉取」（用户点才去邮箱），延续产品克制的原则；对上游的「脏数据」（分片邮件、缺时间字段、截断）做降级处理而不是报错，让链路在现实环境中真正可用。

## 10. 面试叙事与追问速查

### 10.1 一句话故事线

> 「我做了个多 Agent 量化研究工具，先用 4 个假设写了 PRD，然后访谈了一位真实的 PTrade 研究者——结果 3 个假设被推翻：他不缺时间（单票 2–3 分钟），不在意隐私（"都无所谓"），付费只认效果证明。于是我把定位从『省时间+本地优先』改成『不漏+可信+批量』，新增了决策卡片、观察池和效果证明三个需求，定价也改成锚定他真实掏过钱的价位。」

### 10.2 追问速查表

| 追问 | 答案指向 |
|---|---|
| 「需求是拍脑袋的吗？」 | 4 假设、29 问提纲、真实访谈、3 个被证伪（PRD 2.3 对照表） |
| 「本地优先用户说无所谓，你怎么看？」 | 卖点让位于用户真实焦虑（造假焦虑）；本地化保留为交付方式，机构线仍为卖点 |
| 「为什么子 Agent 是固定流程而不是让 LLM 自己思考？」 | **本文档第 5 节**：用户信任的是可验证结果、不是黑盒推理；「代码不算错」是模型无关的护城河；确定性决定「结论对不对」，模型决定「话好不好懂」 |
| 「为什么不做交易/荐股？」 | 信任未建立前 AI 输出不接触资金；用户明确拒绝「AI 给方向」 |
| 「怎么定价？」 | 锚定真实付费行为（500–1000 元/年）+ 效果证明解锁高价档 |
| 「巨头（东财妙想）做了怎么办？」 | 妙想做选股、我做复盘；确定性计算与数据源中立是模型无关的护城河 |
| 「你最大的失误/学到什么？」 | ① 把「溯源」当独家卖点被妙想撞车 → 差异化必须是组合不能是单点；② 上游把轮次放邮件主题导致分片拼不起来 → 吃透上游链路本身就是竞争力；③ 样本 n=1 就推翻假设 → 用两阶段访谈 + Go/No-Go 对冲 |

### 10.3 5 分钟 Demo 脚本（以设计决策为单位）

每一步的停顿点不是「功能演示」，而是「设计理由」：

1. **口令登录** → 讲多访客防破坏设计（配置只读、每日额度、会话隔离）
2. **从邮件选一份报告** → 讲信号源接入的产品取舍（不改上游习惯、不碰交易、按需拉取、脏数据降级）
3. **解析预览 + partial 确认** → 讲原则一和二：「跑不跑」由人决定，缺失字段必须人知情；按钮文案「确认风险并启动研究」
4. **多 Agent 运行（实时消息流）** → 讲统筹组队为什么受约束、三个专家为什么并行、运行中为什么能暂停/插话（人给方向）
5. **规则推荐卡片** → 讲「卡片只含程序判定通过的票」：这不是 AI 推荐，是用户策略规则的执行结果 + AI 压缩的消息面；六维对齐东财 7 步心智
6. **运行记录** → 讲可验证（Q12）与效果证明（Q16）：历史不覆盖、可重跑对比——这是信任的入口，也是未来「策略有效性报告」的数据底座
7. **导出 Markdown** → 讲输出定位：研究解读与风险提示，不构成买卖建议

### 10.4 简历 bullet

产品侧：
- 完成 28 分钟深度用户访谈并回填 PRD：推翻 3/4 项产品假设（耗时、隐私、定价），重构定位为「可验证真实 + 确定性计算」，新增决策卡片/观察池/批量处理三项需求
- 完成 6 类竞品分析（东财妙想/问财/慧博/Wind/通用大模型/PTrade 生态），识别妙想「100% 溯源」撞车风险，将差异化锚点从溯源转向确定性计算与数据源中立
- 基于用户真实付费行为（500–1,000 元/年）与效果证明意愿（3–5 万/年），设计免费→订阅→高阶三档商业模型与效果证明机制

实现侧：
- 设计并实现 A 股多 Agent 研究产品（桌面 + 云端 Web 双形态），并打通 PTrade → 邮箱 → 产品的信号摄入闭环
- 构建「确定性规则 + 模型解释」的分层设计：关键数字代码计算、外部事实强制挂证据、模型失败自动回退，实现幻觉可控与全流程可审计
- 输出「规则推荐卡片」形态：只展示程序判定通过的标的，AI 仅聚合消息面与风险，落实「人给方向、AI 执行」的产品原则
